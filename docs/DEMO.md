## Opening: the problem (20 seconds)

“Leaving the hospital should be the start of recovery. Instead, patients have to turn a confusing set of instructions into appointments, reminders, and questions on their own. Homeward makes that next step clear and shows a care team what still needs attention.”

Avoid claiming reduced readmissions or missed appointments: this prototype has not measured those outcomes.

## Show one person's journey (75 seconds)

1. Open **My recovery** for Alex Morgan. Identify the next follow-up and the unanswered laboratory question.
2. Click **View source** on the follow-up. Show the exact sentence supporting the task and its seven-day deadline.
3. Open **Ask Homeward**, select **TrueForge agent**, and ask: **“What paperwork should I bring to my follow-up? Cite the discharge record.”** Show the actual answer and source reference. If no model is connected, explicitly demonstrate **Source search** and explain that it is retrieval without an LLM.
4. Ask the live agent: **“Propose a reminder for my follow-up task. Do not execute it.”** Or use the task's bell to demonstrate the deterministic workflow if AI access is unavailable.
5. Open the pending approval from the top-right bell. Show that a reminder is proposed, not sent. Approve it.

## Show what happens when things go wrong (40 seconds)

1. In the approved reminder dialog, check **Simulate a timeout after saving**.
2. Click **Create local reminder**. The simulated lost response appears.
3. Click **Retry safely**. The same saved receipt is returned.
4. Download the `.ics` file. State that this is a local calendar reminder, not a booked appointment or sent message.
5. Open **Agent activity**. Show approval, timeout, and deduplication events.

## Close with visibility and evidence (45 seconds)

1. Open **Care team** to show Alex's progress, Jordan's overdue follow-up, and the item needing clarification.
2. Return to **Agent activity** and show the guardrail report generated by `npm run eval`.
3. Explain the controls: one patient's tools per agent session, no model-accessible approval endpoint, bounded execution, source validation, and real token/cost reporting when the provider supplies it.
4. Close: **“We’re making follow-through easier for patients and visible to care teams, while keeping the agent’s actions reviewable and under human control.”**

## Judging criteria

| Criterion         | Evidence to show                                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------------------ |
| Clarity           | One person, one discharge plan, one approved next step                                                             |
| Problem statement | Fragmented instructions become missed or unclear follow-up tasks                                                   |
| Implementation    | Running UI, SQLite persistence, real TrueForge/MCP connection, source search, calendar output                      |
| Presentation      | A short narrative, visible failure recovery, and an honest distinction between real integrations and demo fixtures |

## Before presenting

- Start Homeward and TrueForge.
- Configure the event's model and run `npm run setup:trueforge`.
- Run `npm test`, `npm run eval`, and `npm run smoke:trueforge`.
- Use the in-app reset only when you are ready to remove local demo changes.
- Keep the Agent activity page ready for the reliability demonstration.
- Confirm the browser layout at the presentation resolution; DOM tests are not screenshot validation.
